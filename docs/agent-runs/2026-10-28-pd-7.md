## Rulings

- **Ruling: new tokens go in `theme/kitB.ts`, imported by path, not added to `theme/color.ts`, `shadow.ts` or `theme/index.ts`** - the coordinator forbids editing PD-3 files. design.md section 6 names values section 2.1 and 4 do not list: `rgba(0,0,0,0.35)` on-finish chip, `rgba(0,0,0,0.4)` empty hero segment, `4px 4px 0 accentEdge` primary step card (not `shadow.pop`, which carries the inset highlight), `2px 2px 0 accentEdge` timeline pay square, `3px 3px 0 bg` score now block. Shadows are built from colour tokens, so no hex is duplicated. The barrel re-exports `overlay` and `kitShadow`. - Cost if wrong: move five lines into the part-A files and delete one.
- **Ruling: no `@/ui` alias; screens import `'../ui'`** (see above). - Cost if wrong: two config lines.
- **Ruling: gallery lives in `src/ui/gallery/`, not `src/kit/`** - same reason as PD-3's folder ruling (the plan, standards and ESLint config say `src/ui`). The plan names `src/kit/KitGallery.tsx`; the coordinator addendum says the kit folder is `src/ui`. Split into one file per section so no file nears the 400-line lint limit. - Cost if wrong: a folder rename.
- **Ruling: `Screen` uses a plain `View` with the Android status-bar height as top padding, not `SafeAreaView`** - RN 0.88's `SafeAreaView` is `@deprecated` and is a plain `View` on Android; `react-native-safe-area-context` is not a dependency and I may not add one. Swap in real insets when a setup task adds that package. - Cost if wrong: one function.
- **Ruling: no icon library; the bell, nav icons and chip glyph are drawn from small square Views** - no dependency allowed. They are decorative (hidden from screen readers); the labels carry the meaning. Visual fidelity to the mockup icons is approximate. - Cost if wrong: swap `BellIcon`/`NavIcon`.
- **Ruling: `ReasonRow` renders the direction words itself** (`lowers your score · <caption>`), `caption` is optional detail - the plan's test ("caption includes `lowers`") would only test the fixture if the component passed the caption through. The row is one accessible element whose label carries title and direction. - Cost if wrong: callers pass the whole phrase; one line.
- **Ruling: `HeroPaymentCard` amount uses `adjustsFontSizeToFit` with `numberOfLines={1}` and `minimumFontScale` 0.6** - an amount must never lose a digit; an amount that cannot fit shrinks. This is the one place the kit shrinks type, and it is an amount, not a range. The sheet's amount in the gallery does the same. - Cost if wrong: remove two props and accept truncation.
- **Ruling: ranges cap their own font growth instead of shrinking** - `ScoreRangeText` XL 1.1, M 1.3, and the `StatTile` value 1.1 (`maxFontSizeMultiplier`). design.md 3 forbids shrinking a range and the plan forbids truncation, and `numberOfLines={1}` alone ellipsizes at large font. At 360dp the XL range (about 255dp) fits a 280dp card only below roughly 1.1x, and a 30px range in a half-width tile (about 122dp inner) is tight even at 1x. These are my width estimates, not measurements. **To be confirmed on a device** (CHECKLIST.md has the step). - Cost if wrong: tune two constants; screens may need to stack stat tiles in one column at large font scale.
- **Ruling: zone colour is matched by `name`** (case-insensitive Poor/Fair/Good/Excellent), falling back to position - props carry names, not token keys. The "now" and plan blocks are positioned on the 0..1 scale of min(from)..max(to) and ignore the 3px gaps between segments (a few dp of error at a boundary). Percentages are clamped to 0..100. An empty `zones` list draws no bar and does not crash.
- **Ruling: timeline dates parse from ISO strings with `Date.UTC`; a date outside today..today+30 is not drawn** - never an argless `Date`. The strip's a11y sentence (supplied by the caller) still names it. A lane with no `due` draws no Due marker, asserted with `includeHiddenElements: true` so the test fails if the marker were hidden by accident.
- **Ruling: `BottomSheet` fades instead of sliding when reduce motion is on** (`Modal animationType`), tested by mocking `useReduceMotion`. Close is first in render order (title row is `row-reverse`) and the scrim is hidden from screen readers but closes on tap and on the Android back button.
- **Ruling: bars are drawn at their final width, no fill animation** - same as PD-3's press ruling: it satisfies reduce motion either way and cannot be asserted reliably under Jest. `useReduceMotion` is used where something does slide (the sheet).
- **Ruling: `BeforeAfterBar` hatch is rotated 2px stripes at a 4px pitch, counted from the measured width (`onLayout`)** - no SVG. Before the first layout there are zero stripes (nothing flashes); the test fires a layout event.
- **Ruling: `DashedRule` clips a taller dashed box to its top edge** - Android only draws dashes reliably on a uniform border. Shared by the score card and the hero.
- **Ruling: `CardTile` imports `formatPercent` from `@credit-coach/engine`** - the plan gives it `utilPercent: number`, and the label text needs a string; formatting stays in the one tested place. Other components take strings.
- **Ruling: pay-by chip text is the caller's label; `soon` adds the `⚠ ` prefix and the due-soon tint** - the non-colour signal is in the text.
- **Ruling: `PlanStepCard` index is zero-based** (`plan-step-0` as the plan's testID says) and shown as `01`.
- **Ruling: `FloatingNav` and the sheet/tiles use `minHeight`** (68, 92, 150, 58 ...) never `height`, per the PD-3 lesson; the plan says "height 68". The `tablist`/`tab` roles are used for the nav (`selected` state), not `button`.
- **Ruling: the gallery also screenshots the open bottom sheet** (`kit-chrome-sheet.png`), so 8 PNGs rather than the plan's 7.
- **Ruling: `Screen` and `Header` are not wired to a router or to the nav**; the floating nav is placed by the screen, not by `Screen`.

## Self-check against design.md (stand-in for `design-checker`) and the PD-3 lessons

- Radius 0 everywhere except status dots (6, 7), the 4px nav dot, the due circle and the legend circle; asserted per component.
- Colours only from tokens: the part-A `no-raw-colors` guard scans every new file under `components/` and `primitives/` on each run (never red at a commit); ESLint `noRawHex` covers the gallery and `App.tsx`.
- Touch targets: whole-row 48dp for date rows, stat tile, nav tabs, header buttons, sheet Close, what-if tile; `minHeight` not `height`.
- Amounts and ranges `numberOfLines={1}` (ranges also `flexShrink: 0`, no `adjustsFontSizeToFit`, font-scale cap); hero amount shrinks rather than truncates.
- Status is never colour alone: `⚠ OVER` / `✓ ON TARGET`, `⚠` on a soon chip, `✓ PAID`, direction words on reason rows, nav dot plus weight, "N new" in the reminders label.
- Charts: before/after bar, zone bar and timeline strip are single `image` nodes with sentence labels containing the numbers; the label is dynamic.
- Live regions: none added; `announce()` exists for screens. The gallery calls it on mark-paid/undo and sheet confirm.
- Tests assert accessibility props, labels, roles and displayed text; mutation spot-check: forcing the Due marker to always render failed 2 timeline tests.
- Fixed copy verified verbatim: disclaimer, AI label and fallback label. The mark-as-paid note appears in the gallery sheet as the screen will show it.
