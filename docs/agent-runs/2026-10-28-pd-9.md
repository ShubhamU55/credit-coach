## Rulings

- **Ruling: paid steps stay listed** - the plan is rebuilt from "current state plus recorded payments added back", and each card's payments settle its steps in step order - design 6.8 says paid steps are never removed, but a plan recomputed only from the current state would drop them and renumber - cost if wrong: if rules or cash change after a payment the attribution can look odd (accepted for the demo).
- **Ruling: the primary step is the earliest unpaid by pay-by date, ties by step number** - design 7.3 - after 01 and 03 are paid the primary is step 05 (24 Oct), not 02 (4 Nov).
- **Ruling: no Undo** - `DemoRepository` has no undo and I do not own it. The kit's paid card renders an Undo button, so it announces "Undo is not available in the demo yet." and changes nothing. The sheet's Done state omits the secondary Undo. Follow-up for the repository owner.
- **Ruling: the 10% switch and the cash edit are screen state** - the repository has no setter for them. The switch starts from `rules.aimFor10`. The admin moment is reproduced by seeding the repository with other rules (tested).
- **Ruling: bad deep-link amounts are ignored, bad cards show an error** - the sheet never records on open; only the Confirm tap does, and a second tap is blocked after success. A valid `amount` param only prefills "Other".
- **Ruling: the sheet is rendered inside the existing `formSheet` route, not the kit `BottomSheet`** - that kit component is a `Modal`, which would nest a modal in a native sheet - cost if wrong: the grabber and scrim come from the native sheet.
- **Ruling: pay-by "soon" = within 1 day** - a constant (`SOON_DAYS`); the admin reminder offsets are not available yet.
