## Rulings

- **Ruling: one route, in-screen steps (home / configure / result)** - I own only `app/score.tsx`, so what-if results cannot be new routes - cost if wrong: Android back needed a `BackHandler` effect (done); deep links to a result are impossible.
- **Ruling: "barely moves" means the range centre moves by 2 points or less** - the kit offers three directions and the engine has none - cost if wrong: a threshold constant (`BARELY_MOVES_POINTS`) to change.
- **Ruling: reasons with direction `flat` are left out of the rows** - the kit `ReasonRow` only words "lowers" or "improves" and a flat row would be a lie - cost if wrong: fewer than three rows on a thin profile.
- **Ruling: no Header or FloatingNav on Score** - the shell and Home streams own navigation chrome and no tab routes exist yet; the screen has "Back to Home" (`score-link-home`, kept for `onboarding-try-sample.yaml`) - cost if wrong: add `Header` and `FloatingNav` when the nav lands.
- **Ruling: "Refresh sample report" not built** - nothing in the demo data can refresh; a button that does nothing is worse than none - cost if wrong: one `TextAction` once PD-11/PD-16 define it.
- **Ruling: "How we estimate" is an inline text toggle** - no explainer screen exists - cost if wrong: replace with a sheet.
- **Ruling: the apply what-if is the card/loan product `card`** - the engine models an application as its inquiry only, so the two products score the same - cost if wrong: add a product picker.
- **Ruling: cash for follow-plan is `profile.cashForCards`** - same source the Plan screen should use - cost if wrong: the with-plan range would differ from Plan.
- **Ruling: the guard threshold N uses `DEFAULT_GUARD_CONFIG` (2)** - admin-editable config does not reach the app yet - cost if wrong: pass the live config through the adapter.
- **Ruling: the anchor score (724) is shown in the footer** - it is the bureau-reported figure, labelled "Last reported", and the ticket's acceptance requires it; the predicted score is never shown as one number.
