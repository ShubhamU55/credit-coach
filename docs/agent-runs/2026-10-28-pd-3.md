## Rulings

- **Ruling: kit lives in `apps/mobile/src/ui/`, not `src/kit/`** - `docs/parallel-streams.md` and the ticket say `src/kit/**`, but Plan 4a, `docs/standards.md` and the existing `apps/mobile/eslint.config.js` (which exempts `src/ui/theme/**` from the raw-hex ban) all say `src/ui/`. Using `src/kit/` would have failed lint on the token files unless I edited a config I do not own. PD-7 has to use the same folder so its components land beside mine. - Cost if wrong: a folder rename plus one config line.
- **Ruling: add `'@parcel/watcher': false` to `allowBuilds` in `pnpm-workspace.yaml`** - `npx expo install jest-expo ...` failed with `ERR_PNPM_IGNORED_BUILDS` (pnpm 12 refuses an install with unreviewed build scripts). The existing entries (`sharp: false`) show the pattern; `false` denies the script, which is only an optional native-watcher fallback. This is a shared hotspot file, so the change is one line. - Cost if wrong: another stream's rebase conflicts on that file; keep both sides.
- **Ruling: `tsconfig.json` gets `types: ["jest", "node"]` and `@types/node` is a dev dependency** - TypeScript 6 no longer includes `@types/*` automatically, so `describe`/`expect` and `fs` in the guard test did not typecheck. `@types/node` was added with `npx expo install`. - Cost if wrong: remove two lines.
- **Ruling: `useAppFonts()` returns `true` after a load error (with a `console.warn`)** - the plan says "returns true when ready". Blocking on a font failure would leave the app on a blank screen forever; the system font is a readable fallback. - Cost if wrong: one condition.
- **Ruling: `fontFamily` lives in `theme/fontFamily.ts` and is re-exported from `fonts.ts`** - so theme code and tests never import the `.ttf` assets. The public name `fontFamily` from `ui/fonts` is as the plan says.
- **Ruling: fonts are imported from per-weight paths** (`@expo-google-fonts/fraunces/400Regular`) - the package root pulls in every weight and would bloat the bundle. - Cost if wrong: swap the import lines.
- **Ruling: no 80 ms press tween in `PopPressable`** - the pressed state is applied in one frame. That is also what reduce-motion asks for, so the rule holds either way. The plan allowed the tween only "for the Animated variant", and a tween cannot be asserted reliably under Jest. `useReduceMotion` ships (tested) for the components that do animate (bar fills, sheet slide, task 8 and 10). - Cost if wrong: add an `Animated` variant to `PopPressable`.
- **Ruling: `PopPressable` tracks `pressed` with `onPressIn`/`onPressOut` state instead of the `Pressable` style callback** - RNTL v14 only fires handlers that exist as props; `fireEvent(el, 'pressIn')` finds nothing when Pressable keeps pressed state internally. Same visible behaviour. - Cost if wrong: none.
- **Ruling: `PopButton` uppercases the label string in JS** (and keeps `textTransform: 'uppercase'` in the type scale) - the plan's test needs the rendered text to be `TRY SAMPLE PROFILE`. The accessible name stays the original sentence-case label so TalkBack does not spell capitals.
- **Ruling: two shadow tokens added beyond design.md section 4** (`switchThumbOff`, `switchThumbOn`) and `noShadow` - design.md 6.10 gives the switch-thumb shadows only in prose (`2px 2px 0 #3A3A44`, accentEdge). The raw-colour guard forbids a literal in a component, so they live in `theme/shadow.ts`. The thumb "on" offset (2px) is my reading of "an accentEdge shadow". - Cost if wrong: edit two strings.
- **Ruling: `AmountInput` strips non-digits in `onChangeText`** - amounts are integer rupees (standards.md) and `number-pad` on Android can still produce `.` and `,`. Screens receive digits only.
- **Ruling: `AmountInput inline` is the borderless Number M variant only** - design.md also describes an "EDIT" text action tied to the input, but the plan's props do not include it. The screen (PD-9) composes it with `TextAction`.
- **Ruling: the `radiogroup` container in `ChoiceRows` is not `accessible`** - an accessible parent would swallow the radios on TalkBack. RNTL `getByRole` only sees accessible nodes, so the test reads the `accessibilityRole` prop by testID.
- Fraunces `estimateTag` line height 24, `numL` 60 and `title` 16/22 are my picks inside the ranges design.md 3.2 gives ("60-62", "15-16", no line height).
