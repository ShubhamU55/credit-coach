- _Round 1_: task review SPEC ✅, but 5 Important + 7 Minor quality issues, all 4 of the implementer's own self-flagged concerns confirmed real with command-level evidence (`which jq`, `gh --help`). One controller ruling, on a genuine plan-internal conflict: this ticket's own brief (plan line 878) names `pm-sync`'s card fields as `owner/scope/merge_gate/handoff`, but the plan's actual board-bootstrap ticket (`W5-2`, line 1100, not yet built) names a completely different field set. Ruled: fix `pm-sync.md`'s real defect (an over-restrictive "all 4 fields must exist" precondition) by making field resolution generic, rather than inventing either field set as canonical — neither this ticket's `Files:` list nor its scope covers `W5-2`'s board.
- _Round 2 — the critical finding._ The round-1 fix round self-reported one residual as only partially closed. A full `security-reviewer`/opus pass (not a routine re-review) **reproduced a working remote-code-execution path**: a crafted PR filename could break out of `pr-reviewer.md`'s worked-example `node -e` script (via a literal `'` or `"` in the path, not sanitized before being spliced into the script's own source text), and a fixed, in-repo heredoc delimiter (`UNTRUSTED_EOF`) had no collision check, independently letting untrusted text terminate a heredoc early and inject a shell command. **Impact: this agent holds the GitHub token that posts the merge-gate (G8) verdict, so a malicious PR could have gotten itself approved by compromising its own reviewer.** Rated CRITICAL under `.claude/rules/code-review.md`'s own severity table — explicitly not a parkable residual. Mid-round-2 dispatch, the implementer agent was interrupted twice (once by an account rate/spend limit, once by a session-boundary process teardown) leaving real, substantial uncommitted work in the worktree; rather than reset it, a fresh implementer was dispatched to verify and complete the existing WIP (after a collision check with a newly-appeared peer session, per the Wave 1 concurrent-writer lesson). The completed fix moved every untrusted value (including `path`/`line`) to reach the `node -e` script only via `process.env`, replaced the fixed delimiter with a per-run random token plus a collision check, and fixed a confirmed-real `gh` CLI fact error (`pm-sync.md` was reading a `dataType` field the real `gh project field-list` doesn't expose). The fix was independently verified by reconstructing and running all 3 original exploit strings plus 9 additional hostile strings in a real Git Bash + Node harness against both the old and new procedure text — all fired as working exploits against the old text and were inert against the new.
- _Round 3_: the round-2 security review found one more issue, HIGH (not an injection — a plain shell-scripting bug): the `node` script's fail-closed `process.exit(1)` had no effect on the surrounding shell, so `gh api`'s review POST ran unconditionally even on invalid/failed data, meaning the agent's own Stop rules couldn't actually fire in time. Fixed with a 2-line guard (`PAYLOAD=$(node -e '...') || exit 1; [ -n "$PAYLOAD" ] || exit 1`), verified with a stub-`gh` shell-function harness showing 8 negative cases now correctly stop before the POST and 1 positive control confirming the happy path still works. Final re-review independently reproduced the same cases from scratch and confirmed closed.

Merged `3485e8c..9c719c0`.
