# PD-17 polish (G8 advisories, apps/mobile)

## What changed (commit `4c8a667`)

1. **Score FloatingNav.** `ScoreScreen.tsx` renders `FloatingNav active="score"`, wired like Plan (`router.navigate('/home')`, `'/plan'`; the Cards tab has no screen and does nothing, as on Plan). `score-link-home` and `score-link-home-unavailable` are kept (Jest tests use them; no Maestro flow does). No flow id changed. `maestroFlow.test.ts` and `demoPathFlow.test.ts` pass.
2. **MarkPaid double-submit.** `recordAndSummarise` now never throws once `recordPayment` has succeeded: the summary runs in its own try/catch and falls back to `GENERIC_RECORDED_LINE`; a card missing after the write also gives the generic line (dev warn). The sheet resets its guard only in the catch, which can now only be reached when `recordPayment` itself threw. Test: `listCards` throws after a successful write gives one payment, Done shown, no Confirm left.
3. **Score engine errors.** `guarded()` now treats any `Error` as an engine refusal except programming errors (`TypeError`, `ReferenceError`, `SyntaxError`, `EvalError`, `URIError`), which still rethrow. Dev-only warn kept. Predictor failure gives the existing "We can't estimate your score right now" view; a planner failure on the main view hides only the with-plan range (same as the existing RangeError behaviour); a planner failure on a what-if tile gives the existing what-if error view.
4. **demo-path.yaml header** now points to `docs/test-reports/maestro-2026-10-30-pd15-demo-path.md` (6/6 on the second full run, 4/6 on the first).
5. **Test strictness.** `demoPathFlow.test.ts` matches quoted testID literals or an exact template (`plan-step-<n>-mark-paid`, `mark-paid-choices-<key>`); `seed.test.ts` adds masked PAN and mobile edge cases (lowercase x, wrong X count, missing `+91 `, trailing newline); new `src/shell/appConfig.test.ts` pins `allowBackup: false` and the three `blockedPermissions`.

## Rulings

- Ruling: the Score screen keeps the main view when only the planner fails on the home extras (with-plan range hidden), and shows "can't estimate" only when the predictor fails. Cost if wrong: if the owner wanted the unavailable view for a planner failure too, a user with a planner invariant error still sees an estimate without the with-plan range; one condition change in `ScoreScreen.tsx`.
- Ruling: plan sheet copy stays "Paid today, 21 Oct" although `docs/design.md` says "Paid on today, 21 Oct". `docs/design.md` is owned by the design workflow, so it is not edited, and the app is not changed. Cost if wrong: a design review flags a one-word copy difference; fixing it is a one-line change in `MarkPaidSheet.tsx` plus its test, or a design.md correction.
- Ruling: all `Error`s except the programming-error classes count as engine refusals. Cost if wrong: an engine bug that throws a plain `Error` would be hidden behind the unavailable view instead of crashing, visible only in the dev warning.
