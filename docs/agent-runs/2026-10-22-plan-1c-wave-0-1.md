# W1-4 fix round 1: findings and binding rulings (sent to the implementer 2026-10-22)

Principle: once a `git commit` is detected, either read EVERY part of its message literally and validate it (format + no attribution, via `checkCommitMessage` in contracts.mjs), or BLOCK (exit 2) with a hint. Never pass unread.

## A. `.claude/hooks/pre-bash-commit-quality.cjs` (Critical)
1. **Detect commits by parsing, not by substring.**
   - Tokenize with the vendored `lib/shell-scan.cjs`.
   - Split on `&&`, `||`, `;`, `|` and newlines, and evaluate each `git … commit` segment on its own.
   - Recognize `-c k=v`, `-C dir`, `--git-dir`, `--work-tree`, extra whitespace and `GIT_*=` env prefixes.
   - Non-git commands such as `grep -m 1 "git commit" CLAUDE.md` must NOT trigger.
2. **Accepted message forms** (all parts are combined into one message):
   - `-m` / `--message` / `--message=` when the value is single-quoted, or double-quoted with no `$` or backtick
   - `-m"v"`
   - combined short flags ending in `m` (`-am`, `-sm`, `-asm`)
