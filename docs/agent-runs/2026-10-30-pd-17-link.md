# PD-17 link: mobile app to the Supabase backend (2026-10-30)

Branch `feat/pd-17-app-backend`, worked by hand, test-first. Scope: `apps/mobile/**` only.

## What changed

- `src/backend/`: config (https-only env read), one lazy supabase-js client (in-memory session,
  `persistSession: false`, `autoRefreshToken: true`), background `startBackend` (anonymous sign-in then
  the single `coach_rules` row, 3 s per step, never throws), strict row parser mirroring the DB CHECK
  ranges, `BackendBootstrap` (renders nothing, mounted in `_layout.tsx`).
- `DemoRepository.applyRules`: replaces the rules, no-op and no notification when unchanged,
  `reset()` keeps them. Home, Plan and Score recompute through the existing `useRules` hooks.
- `explain/client.ts`: `getAccessToken` getter read at call time; `configFromExpoEnv` wires the
  in-memory anonymous token in, so a deployed function can return source `ai`. Grounding check and
  template fallback untouched.
- Dependencies (JS only, no native module, `android/` unchanged): `@supabase/supabase-js`,
  `react-native-url-polyfill`.

## Findings

- supabase-js sets `url.protocol`; React Native 0.88's built-in `URL` has no setter, so `createClient`
  throws on device without a spec URL class. A test with RN's own URL class reproduced it (RED), the
  polyfill (loaded lazily, only when a backend config exists) fixes it (GREEN).
- `useExplanation` is not called by any screen: the Plan screen renders `AIExplanation aiWritten={false}`
  with the engine template. The AI wording therefore cannot show until a screen uses the hook. Not done
  here (screens are out of scope to avoid a conflict with `feat/pd-17-polish`).
- Home and Plan build engine rules from `DEFAULT_COACH_RULES`, so `pay_by_buffer_days` and
  `planner_step_order` are validated but not applied. Only threshold, excellent, reporting basis and the
  guard line take effect.

## Not run

Live Supabase, a device or emulator, Maestro. Everything above is covered by Jest with mocked fetch.
