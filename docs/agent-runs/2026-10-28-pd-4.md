## Maestro: NOT RUN (build blocked)

The release APK could not be built on this machine, so neither flow ran against the new app, and no report was committed.

- Cause: Windows `MAX_PATH` (260) in the CMake/ninja step of `:app:buildCMakeRelWithDebInfo`. Adding `expo-router` links `react-native-safe-area-context` and `react-native-screens`, whose autolinked codegen object paths exceed the limit under `C:\Users\55\cc-pd4\apps\mobile\android\app\.cxx\...` (`ninja: error: mkdir(safeareacontext_autolinked_build/...): No such file or directory`). Before the dependency change the same build worked, because no such library was linked.
- Also found: `react-native-gesture-handler`, `react-native-reanimated` and `react-native-worklets` (optional peers of expo-router that pnpm installed) fail the same way (329-character path). `expo.autolinking.android.exclude` in `package.json` removes them from the build but does not fix safe-area-context. I tried a `subst` drive: Gradle resolves back to the real path, so it did not help. I reverted the exclude.
- Not tried (needs the owner): enabling `LongPathsEnabled` (admin registry change under `HKLM\SYSTEM\CurrentControlSet\Control\FileSystem`, currently 0), or building from a much shorter checkout path such as `C:\p`.
- I also set `reactNativeArchitectures=x86_64` in the generated, git-ignored `android/gradle.properties` to cut build time.
- The emulator was started by me (Pixel_7, `-no-window`) and shut down with `adb emu kill`; the `X:` subst was removed.
