# Test layers

Every layer below is owned by `test-automator` (`.claude/agents/test-automator.md`), which lands
accepted tester proposals into it. Testers (`functional-tester`, `edge-case-hunter`, `api-tester`,
`ui-tester`, `integration-tester`) propose; they never write a test file themselves. A proposal is
`{ name, layer, file, assertion, criterion }`. The Layer column below names each row and, in
parentheses, the `layer` enum value a proposal uses to target it. A row with "no enum" isn't
addressable by a proposal yet — see its Gate column for why.

## Notes

- **Engine coverage gate** (`.claude/rules/testing.md`, `docs/standards.md`): `packages/engine`
  must stay at ≥ 90% line coverage; `pnpm --filter @credit-coach/engine test` runs with
  `--coverage` (v8) already configured in `packages/engine/package.json`.
- **`pnpm verify`** (root `package.json`) runs lint, typecheck and every workspace's `test` script,
  so the engine, edge-case, property and tooling layers all run under it without a separate CI
  step. Admin E2E runs as its own CI job (`admin-e2e`, `.github/workflows/ci.yml`), which does
  execute Playwright against a live Next.js server in CI, because that needs a browser the
  `verify` job doesn't start.
- **CI never runs Maestro.** There's no Android emulator in CI. The `maestro-evidence` job
  (`.github/workflows/ci.yml`, `.claude/hooks/bin/maestro-evidence.mjs`) only checks that a
  Maestro report someone already ran **locally** against the emulator was committed to
  `docs/test-reports/maestro-*.xml` and passed — it never invokes `maestro test` itself. A PR
  that changes `apps/mobile/**` fails this check unless that locally-run report is up to date.
- **Flaky-test quarantine**: `test-automator` is the only agent allowed to skip a landed test, and
  only from an explicit `flaky[]` input naming a linked issue — `it.skip`/`test.skip` for
  Vitest/fast-check, `test.fixme`/`test.skip(true, …)` for Playwright, both carrying
  `quarantined: #<issue>` — never a silent or unexplained skip. Maestro and Supabase-API flaky
  tests can't be quarantined this way yet (see `.claude/agents/test-automator.md`).
- **Evidence for judges** (CLAUDE.md, spec §8.6 and §10): Maestro reports and screenshots live in
  `docs/test-reports/`; Playwright's HTML report is uploaded as a CI artifact on failure
  (`.github/workflows/ci.yml`, `admin-e2e` job) rather than committed, since it's a generated
  report, not source evidence.
